## Source Review

The skill has a clear session-continuity outcome: compact the current
conversation into a handoff document that a fresh agent can use without
duplicating context. It is intentionally simpler than `build-handoff`.
`build-handoff` is repository-state driven and covers branch, PR, diff, and test
state; `handoff` is conversation/session driven and writes outside the
workspace by default.

Initial source gaps found:

- The procedure correctly says to save the document to the operating system temp
  directory, but it did not explicitly require reporting the saved file path to
  the user.
- The "What Not To Do" section did not explicitly prevent agents from turning a
  session handoff into the implementation-oriented repository handoff now owned
  by `build-handoff`.

Readiness checklist notes:

- Metadata is coherent for beta: stable lowercase id, distinct name,
  outcome-oriented summary, expected profiles, and intentional target
  enablement.
- Activation is specific and separate from adjacent skills. `prepare the next
  session` maps to session continuation, while `build-handoff` handles
  implementation continuity.
- Safety metadata matches the procedure: file writes are required, shell and
  network access are not required, and there are no scripts.
- The output contract is concise and testable for beta.

## Findings

1. The skill should tell agents to report the exact saved file path after
   writing the handoff.
2. The "What Not To Do" section should explicitly direct implementation-oriented
   branch/PR/diff/test handoffs to `build-handoff`.

## Required Edits

- Promoted `skills/handoff/skill.yml` from `draft` to `beta`.
- Added a procedure step requiring the agent to report the exact saved file
  path after saving the handoff.
